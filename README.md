# テニス ダブルス ローテーション表ジェネレーター 🎾

テニスのダブルス試合のローテーション表を自動生成する Web アプリです。高度な公平性アルゴリズムにより、出場回数・対戦相手・ペア組みを最適化します。

## ✨ 特徴

- 🎨 可愛いパステルデザイン + Nekos.best API 背景画像
- 📱 スマホ対応（iPhone 11 検証済み）
- ⚖️ **高度な 4 層評価アルゴリズム**
  - L1: 1 人評価 - 出場回数に基づき主役を選択
  - L2: 2 人評価 - 対手を選択（連続性考慮）
  - L3: 3 人評価 - パートナーを選択（文脈認識 + 連続性考慮）
  - L4: 4 人評価 - 最適な 4 人組合を評価
- 🎯 複数コート対応（1 ～ 3 コート）
- 📊 統計表示機能（出場回数・ペア回数・対戦回数）
- 💾 PNG 画像保存
- 🔍 デバッグログ出力（?debug=true で表示）
- 🔒 完全クライアントサイド実行（データ送信なし）

## 🎯 4 層評価体系

### システム概要

このシステムは**段階的な 4 層評価**を採用しており、プレイヤー数の増加に応じて評価が複雑になります：

| レイヤー | 評価人数 | 目標                                              | 重み数 |
| -------- | -------- | ------------------------------------------------- | ------ |
| **L1**   | 1 人     | 最も公平な主役を選出                              | 3 個   |
| **L2**   | 2 人     | 主役に最適な対戦相手を選出（連続性考慮）          | 6 個   |
| **L3**   | 3 人     | 主役に最適なパートナーを選出（文脈認識 + 連続性） | 5 個   |
| **L4**   | 4 人     | 最適な 4 人組合を評価（連続性考慮）               | 4 個   |

### L1：1 人評価（主役選択）

**目標**：出場回数が最も少ないプレイヤーを主役として選出

**重み設定**：

| 重み                | 値  | 意味           |
| ------------------- | --- | -------------- |
| `PLAY_COUNT_SORT`   | 100 | 出場回数の重み |
| `LEAD_PLAYER_COUNT` | 50  | 主役回数の重み |
| `CONSECUTIVE_REST`  | 10  | 連続待機補償   |

**スコア計算式**：

```
スコア = 出場回数×100 + 主役回数×50 - 待機数×10
→ スコアが低いほど優先的に主役として選出される
```

### L2：2 人評価（対戦相手選択）

**目標**：各主役に対して最適な対戦相手を選出（連続性を考慮）

**重み設定**：

| 重み                           | 値   | 意味                     |
| ------------------------------ | ---- | ------------------------ |
| `MATCH_HISTORY_SELECT`         | 100  | 対戦履歴の重み           |
| `PLAY_COUNT_SELECT`            | 50   | 出場回数均衡の重み       |
| `PARTNER_HISTORY`              | 10   | ペア履歴の重み           |
| `CONSECUTIVE_MATCH_OPPONENT`   | 25   | 連続対戦回数の重み       |
| `CONSECUTIVE_PARTNER_OPPONENT` | 15   | 連続パートナー回数の重み |
| `PLAYER_NUMBER`                | 0.01 | タイブレーカー           |

**スコア計算式**：

```
スコア = -(対戦回数×100 + 出場回数×50 + ペア履歴×10
         + 連続対戦×25 + 連続パートナー×15 + プレイヤーID×0.01)
→ スコアが高いほど優先的に対戦相手として選出される
→ 連続性重みは同じ対戦相手の連続対戦を避ける
```

### L3：3 人評価（パートナー選択 - コア機能）

**目標**：主役に対して特定の対戦相手に最適なパートナーを選出（連続性を考慮）

**主要機能**：**文脈認識** - パートナーのスコアは対戦相手に依存！

- 同じパートナーが異なる相手に対して異なるスコアを得る
- 例：パートナー A vs 対手 X では高得点、vs 対手 Y では低得点

**重み設定**：

| 重み                          | 値  | 意味                       |
| ----------------------------- | --- | -------------------------- |
| `TRIPLET_PARTNER_HISTORY`     | 50  | 主役とパートナーのペア履歴 |
| `TRIPLET_OPPONENT_HISTORY`    | 30  | パートナーと対手の対戦履歴 |
| `TRIPLET_LEAD_HISTORY`        | 20  | 主役と対手の対戦背景       |
| `TRIPLET_CONSECUTIVE_MATCH`   | 20  | 連続対戦回数の重み         |
| `TRIPLET_CONSECUTIVE_PARTNER` | 15  | 連続パートナー回数の重み   |

**スコア計算式**：

```
スコア = -(主-パペア履歴×50 + パ-対対戦×30 + 主-対対戦×20
         + 連続対戦×20 + 連続パートナー×15)
→ スコアが高いほど優先的にパートナーとして選出される

注意：このスコアは主役、対手、パートナーの3つの要因と連続性を考慮
```

### L4：4 人評価（最終組合）

**目標**：完全な 4 人組合を評価して最適なマッチを生成（連続性を考慮）

**重み設定**：

| 重み                          | 値  | 意味                     |
| ----------------------------- | --- | ------------------------ |
| `MATCH_HISTORY_PATTERN`       | 50  | 4 人間の対戦履歴の重み   |
| `MIXED_BONUS`                 | 100 | 男女混合ペアのボーナス   |
| `PATTERN_CONSECUTIVE_MATCH`   | 20  | 連続対戦回数の重み       |
| `PATTERN_CONSECUTIVE_PARTNER` | 15  | 連続パートナー回数の重み |

**スコア計算式**：

```
スコア = -(パートナー1ペア×50 + パートナー2ペア×50
         + 4人対戦合計×50 + 連続対戦総数×20 + 連続パートナー総数×15)
       + (男女ペア数×100)
→ スコアが高いほど優先的にマッチとして生成される

注意：連続性重みは同じ対手またはパートナーの頻繁な出現を避ける
```

## 🔑 コア概念

### 文脈認識（L3 の鍵）とは？

パートナー選択時に、**グローバルに最適なパートナーを選ぶのではなく、
特定の対手に対して最適なパートナーを選ぶ**。

**例**：

- パートナー A はグローバルに優秀（多くの人とペアを組んだ、多くの人と対戦）
- パートナー B は特定の対手 X に適切（対手 X と対戦経験がない）
- L3 は対手の違いに応じて異なるパートナーを動的に選択
- 対手 X に対面する場合、B を優先的に選択することがある

### 連続性重みとは？

**連続性重み**は、同じ対手またはパートナーが連続して出現するのを制限します。

**例**：

```
プレイヤーAとプレイヤーBが既に3回対戦している場合：
- 連続対戦重み: CONSECUTIVE_MATCH = 25
- 減点: -3 × 25 = -75 点
- この組合を再度選択するのを避ける

プレイヤーCとプレイヤーDが既に2回ペアを組んでいる場合：
- 連続パートナー重み: CONSECUTIVE_PARTNER = 15
- 減点: -2 × 15 = -30 点
- このペアを分割する傾向
```

### 4 層が必要な理由？

1. **L1** は**出場公平性**を確保 - 誰もが機会を得る
2. **L2** は**対戦多様性**を確保 - 常に同じ対手ではない
3. **L3** は**配合最適化**を確保 - 対手背景を考慮したパートナー選択
4. **L4** は**総合最適化**を確保 - すべての関係がバランス

各層は異なる最適化問題を解決し、段階的に進みます。

## 💻 使い方

1. コート数を選択（1 ～ 3）
   - コート数を変更すると、自動的に最小人数（コート数 ×4 名）が選択されます
2. 参加人数を選択
   - 最小人数: コート数 ×4 名（1 コート=4 名、2 コート=8 名、3 コート=12 名）
   - 最大人数: 30 名
3. 参加者名を入力（任意・改行区切り）
   - 省略時は「プレイヤー 1, 2, 3...」と表示
   - 入力人数と選択人数が異なる場合は警告が表示されます
4. 「ローテーション表を生成」をクリック
5. 統計情報で公平性を確認
6. 必要に応じて画像保存

### 処理フロー

```
【L1】主役を選出 (A, B)
  ↓ 重み: PLAY_COUNT_SORT, LEAD_PLAYER_COUNT, CONSECUTIVE_REST
【L2】Aの対戦相手を選出 (vs C) - 連続対戦を考慮
  ↓ 重み: MATCH_HISTORY_SELECT, CONSECUTIVE_MATCH_OPPONENT, CONSECUTIVE_PARTNER_OPPONENT
【L3】Aのパートナーを選出 (vs C, + Dパートナー) - 連続対戦と連続パートナーを考慮
  ↓ 重み: TRIPLET_PARTNER_HISTORY, TRIPLET_CONSECUTIVE_MATCH, TRIPLET_CONSECUTIVE_PARTNER
【L4】(A+D) vs (C+E)を評価 - 総合的な連続性を考慮
  ↓ 重み: MATCH_HISTORY_PATTERN, PATTERN_CONSECUTIVE_MATCH, PATTERN_CONSECUTIVE_PARTNER
マッチを生成！
```
