# テニス ダブルス ローテーション表ジェネレーター 🎾

テニスのダブルス試合のローテーション表を自動生成する Web アプリです。4 ポジション評価アルゴリズムにより、出場回数・対戦相手・ペア組みを最適化します。

## ✨ 特徴

- 🎨 可愛いパステルデザイン + Nekos.best API 背景画像
- 📱 スマホ対応（iPhone 11 検証済み）
- ⚖️ **4 ポジション評価アルゴリズム**
  - ポジション 1: リード選手選択 - 出場回数・連続待機ラウンド数を考慮
  - ポジション 2: ペア選手選択 - 過去ペア関係・対戦経験を考慮
  - ポジション 3: 対戦相手選択 - 新しい対戦パターンを優遇
  - ポジション 4: 対戦ペア選択 - 全関係者との過去履歴を総合評価
- 🎯 複数コート対応（1 ～ 3 コート）
- 📊 統計表示機能（出場回数・ペア回数・対戦回数・ポジション別選択回数）
- 💾 PNG 画像保存
- 🔍 デバッグログ出力（?debug=true で表示）
- 🔒 完全クライアントサイド実行（データ送信なし）
- 💾 ローカルストレージ対応（12 時間の自動有効期限）

## 🎯 4 ポジション評価システム

### システム概要

新しいアルゴリズムは「1 ラウンド × 1 コート」ごとに、4 人のプレイヤーを段階的に選択します：

1. **ポジション 1**: 最も公平なリード選手を選出
2. **ポジション 2**: リード選手のパートナーを選出
3. **ポジション 3**: 新しい対戦相手を選出
4. **ポジション 4**: 対戦相手のパートナーを選出

### 各ポジション詳細

#### ポジション 1：リード選手選択

**目標**：出場機会が少ないプレイヤーを優先

| 評価基準                | 説明                             | 重み |
| ----------------------- | -------------------------------- | ---- |
| `POS1_PLAY_COUNT`       | 出場回数（少ないほど高評価）     | 120  |
| `POS1_POSITION_COUNT`   | ポジション 1 回数                | 50   |
| `POS1_CONSECUTIVE_REST` | 連続待機ラウンド数（優遇）       | -50  |
| `POS1_PLAYER_NUMBER`    | プレイヤー番号（タイブレーカー） | 0.01 |

#### ポジション 2：ペア選手選択

**目標**：ポジション 1 との過去ペア関係を新鮮に保つ

| 評価基準                | 説明                      | 重み |
| ----------------------- | ------------------------- | ---- |
| `POS2_PARTNER_HISTORY`  | ポジション 1 との過去ペア | 60   |
| `POS2_MATCH_HISTORY`    | ポジション 1 との過去対戦 | 40   |
| `POS2_PLAY_COUNT`       | 出場回数                  | 50   |
| `POS2_POSITION_COUNT`   | ポジション 2 回数         | 30   |
| `POS2_CONSECUTIVE_REST` | 連続待機ラウンド数        | -30  |
| `POS2_PLAYER_NUMBER`    | プレイヤー番号            | 0.01 |

#### ポジション 3：対戦相手選択

**目標**：新しい対戦パターンを作り、バリエーションを増やす

| 評価基準                | 説明                        | 重み |
| ----------------------- | --------------------------- | ---- |
| `POS3_PARTNER_HISTORY`  | ポジション 1/2 との過去ペア | 50   |
| `POS3_MATCH_HISTORY`    | ポジション 1/2 との過去対戦 | 40   |
| `POS3_PLAY_COUNT`       | 出場回数                    | 50   |
| `POS3_POSITION_COUNT`   | ポジション 3 回数           | 30   |
| `POS3_CONSECUTIVE_REST` | 連続待機ラウンド数          | -30  |
| `POS3_PLAYER_NUMBER`    | プレイヤー番号              | 0.01 |

#### ポジション 4：対戦ペア選択

**目標**：全 3 人との関係を総合評価して、最適なペアを選出

| 評価基準                | 説明                          | 重み |
| ----------------------- | ----------------------------- | ---- |
| `POS4_PARTNER_HISTORY`  | ポジション 1/2/3 との過去ペア | 50   |
| `POS4_MATCH_HISTORY`    | ポジション 1/2/3 との過去対戦 | 40   |
| `POS4_PLAY_COUNT`       | 出場回数                      | 50   |
| `POS4_POSITION_COUNT`   | ポジション 4 回数             | 30   |
| `POS4_CONSECUTIVE_REST` | 連続待機ラウンド数            | -30  |
| `POS4_PLAYER_NUMBER`    | プレイヤー番号                | 0.01 |

## 🔑 コア概念

### 文脈認識（L3 の鍵）とは？

パートナー選択時に、**グローバルに最適なパートナーを選ぶのではなく、
特定の対手に対して最適なパートナーを選ぶ**。

**例**：

- パートナー A はグローバルに優秀（多くの人とペアを組んだ、多くの人と対戦）
- パートナー B は特定の対手 X に適切（対手 X と対戦経験がない）
- L3 は対手の違いに応じて異なるパートナーを動的に選択
- 対手 X に対面する場合、B を優先的に選択することがある

### 連続性重みとは？

**連続性重み**は、同じ対手またはパートナーが連続して出現するのを制限します。

**例**：

```
プレイヤーAとプレイヤーBが既に3回対戦している場合：
- 連続対戦重み: CONSECUTIVE_MATCH = 25
- 減点: -3 × 25 = -75 点
- この組合を再度選択するのを避ける

プレイヤーCとプレイヤーDが既に2回ペアを組んでいる場合：
- 連続パートナー重み: CONSECUTIVE_PARTNER = 15
- 減点: -2 × 15 = -30 点
- このペアを分割する傾向
```

### 4 層が必要な理由？

1. **L1** は**出場公平性**を確保 - 誰もが機会を得る
2. **L2** は**対戦多様性**を確保 - 常に同じ対手ではない
3. **L3** は**配合最適化**を確保 - 対手背景を考慮したパートナー選択
4. **L4** は**総合最適化**を確保 - すべての関係がバランス

各層は異なる最適化問題を解決し、段階的に進みます。

## 💻 使い方

1. コート数を選択（1 ～ 3）
   - コート数を変更すると、自動的に最小人数（コート数 ×4 名）が選択されます
2. 参加人数を選択
   - 最小人数: コート数 ×4 名（1 コート=4 名、2 コート=8 名、3 コート=12 名）
   - 最大人数: 30 名
3. 参加者名を入力（任意・改行区切り）
   - 省略時は「プレイヤー 1, 2, 3...」と表示
   - 入力人数と選択人数が異なる場合は警告が表示されます
4. 「ローテーション表を生成」をクリック
5. 統計情報で公平性を確認
6. 必要に応じて画像保存

## 📝 実装詳細

### コード構成

| クラス              | 役割                     | メソッド数 |
| ------------------- | ------------------------ | ---------- |
| `ScoreCalculator`   | スコア計算の静的メソッド | 9 個       |
| `RotationGenerator` | メインロジック           | 15 個      |
| `UIController`      | UI 制御                  | 8 個       |

### 主要なメソッド

| メソッド                        | 役割                                  | レイヤー |
| ------------------------------- | ------------------------------------- | -------- |
| `selectLeadPlayers()`           | 各コート向けに主役プレイヤーを選択    | L1       |
| `selectOpponentLeadPlayers()`   | 対戦主役プレイヤーを選択              | L2       |
| `selectPairCandidates()`        | ペア候補プレイヤーを選択              | L3       |
| `calculateMatchScore()`         | 試合スコアを計算                      | L4       |
| `generatePairPatterns()`        | ペアパターンを生成（1 ～ 4 パターン） | L4       |
| `calculateTripletScore()`       | 三人組スコアを計算                    | L3       |
| `calculateConsecutiveScoreL2()` | L2 連続性スコアを計算                 | L2       |
| `calculateConsecutiveScoreL3()` | L3 連続性スコアを計算                 | L3       |
| `calculateConsecutiveScoreL4()` | L4 連続性スコアを計算                 | L4       |

### 処理フロー

```
【L1】主役を選出 (A, B)
  ↓ 重み: PLAY_COUNT_SORT, LEAD_PLAYER_COUNT, CONSECUTIVE_REST
【L2】Aの対戦相手を選出 (vs C) - 連続対戦を考慮
  ↓ 重み: MATCH_HISTORY_SELECT, CONSECUTIVE_MATCH_OPPONENT, CONSECUTIVE_PARTNER_OPPONENT
【L3】Aのパートナーを選出 (vs C, + Dパートナー) - 連続対戦と連続パートナーを考慮
  ↓ 重み: TRIPLET_PARTNER_HISTORY, TRIPLET_CONSECUTIVE_MATCH, TRIPLET_CONSECUTIVE_PARTNER
【L4】(A+D) vs (C+E)を評価 - 総合的な連続性を考慮
  ↓ 重み: MATCH_HISTORY_PATTERN, PATTERN_CONSECUTIVE_MATCH, PATTERN_CONSECUTIVE_PARTNER
マッチを生成！
```
